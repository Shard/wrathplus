# Descriptor table provenance

`crates/benilla-protocol/src/messages/update_object/fields/layout_generated.rs`
is generated by the dependency-free Rust tool `scripts/gen-fields.rs` from this
server protocol reference header (not a file from a game install):

| Layout | Source | SHA-256 of input |
|---|---|---|
| Wrath 12340 | AzerothCore `core/src/server/game/Entities/Object/Updates/UpdateFields.h` in the local playerbots checkout | `d5f4ac389eb717a8ce902cc081a7a1b398794e9f437b3e6dbe380c30d9871590` |

Regeneration (supply the read-only reference header path):

```sh
rustc scripts/gen-fields.rs -o /tmp/azb-gen-fields
/tmp/azb-gen-fields /path/to/UpdateFields.h \
  > crates/benilla-protocol/src/messages/update_object/fields/layout_generated.rs
rustfmt --edition 2021 crates/benilla-protocol/src/messages/update_object/fields/layout_generated.rs
```

Common names remove `FIELD` and use Rust casing, except `PlayerFieldBytes` and
`PlayerFieldBytes2`: these private words must remain distinct from the public
`PlayerBytes` and `PlayerBytes2` appearance words. Power, quest, visible-item and
enchantment groups have one semantic root with native dword offsets: a quest slot is
five dwords (id, state, two `TWO_SHORT` counter words, timer) and a visible item two
(entry, then the permanent and temporary enchant halves). Typed readers interpret
these shapes. Native bit values are not renumbered by these tables.

Until Vanilla removal step 5 the generator also took vmangos's
`UpdateFields_1_12_1.h` and emitted a second (`VANILLA`) table; the Wrath table it
emits now is byte-identical to the one it produced then.
