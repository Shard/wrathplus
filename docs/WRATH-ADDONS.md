# Wrath authored-addon compatibility

## Target and acceptance boundary

Build 12340 / interface 30300, selected explicitly by the Wrath data profile. Vanilla remains the default and retains its Lua 5.0-shaped API. The interpreter is already vendored Lua 5.1; the Wrath host must not apply the Vanilla shim.

This work enables an incrementally tested authored-addon subset, not full stock Wrath FrameXML. Neither successful parsing nor an apparently clickable frame establishes unsupported gameplay API compatibility. Unsupported functions, events, XML features and secure templates must be reported, not implemented as fake successes or authoritative placeholder data.

## Concrete slices

1. Profile-scoped interpreter/handler semantics: Lua 5.1, addon chunk name/private-table arguments, XML handler formal parameters, event/widget dispatch, sandbox and instruction budgets. Preserve Vanilla tests.
2. Existing-loader integration: TOC 30300 gating, dependencies, ordered Lua/XML/includes, addon registry, ADDON_LOADED, account/character SavedVariables, load-on-demand, fresh VM at reload/entry and truthful lifecycle events. No stock UI load or stock bindings activation.
3. Basic Frame/Button/Texture/FontString subset: anchors, visibility, text, clicks and OnUpdate through the original layout/input/render engine. Maintain the native safe overlay and qualified ground bindings alongside the addon VM.
4. Observed player-state readers: explicit supported APIs only, sourced from admitted client state. Unavailable means unavailable, never a fabricated record. Every structured benchmark observation is a separately declared modality.
5. Wider compatibility: extend event/API/widget/XML catalogs with build-12340 references and regressions; secure execution/taint, stock templates, stock FrameXML, bindings/rebinding and gameplay verbs each require separate qualification.
6. External harness contract: host-owned actor/episode/session epochs, observation freshness/frame correlation, bounded held input, ownership, idempotency and admission/execution/completion receipts. This is separate from addon compatibility; no Lua addon becomes a scorer/reset authority.

## Implemented bounded surface (qualification in progress)

The Wrath constructor exposes a named allowlist (`wrath_allowed_engine_functions()`), not the full Vanilla game API. Player readers are `UnitExists`, `UnitName`, `UnitGUID`, `UnitIsUnit`, `UnitHealth`, `UnitHealthMax`, and `UnitLevel`. `UnitIsUnit` reuses existing observed snapshots/token resolution: missing/nonexistent units do not match, existing same tokens match case-insensitively, and distinct tokens match only equal nonzero GUIDs. The binding currently returns numeric 1/nil; its exact build-12340 return type is not independently qualified, so authored observers normalize truthiness rather than depending on that type. Build information reports 3.3.5/build 12340/interface 30300; unresolved GUIDs are nil. Ordinary widget/event, addon registry/dependency/demand-load, SavedVariables, safe scripting, clock and reload helpers are included. Movement, spellcasting, inventory, quest, chat and privileged verbs are absent in this slice. Native W/S/A/D/Q/E and safe logout remain host-owned.

The vendored parser uses a per-state registry flag before any compilation; Lua 5.1 syntax does not leak into a simultaneous Vanilla VM. Wrath handlers use positional arguments rather than legacy `this`/`argN` globals. TOC Lua and XML-referenced Lua share addon name/private-table context. Required/optional dependencies recurse under the 30300 gate. XML include cycles and excessive depth are rejected. Secure template aliases are rejected rather than materialized as ordinary unprotected frames.

Wrath has a 128 MiB Lua allocator ceiling and a shared coroutine-aware, sticky instruction budget. Protected-call wrappers propagate exhaustion; the host rearms once before each frame's event feeds. Counts are conservative, charging calls as well as sampled VM instructions. A combined monotonic quota limits frame/region/font objects to 4,096 per Wrath VM. Native string matching has a separate 100,000-work-step/200-recursive-frame ceiling, including plain-search paths. These are not process isolation or wall-clock preemption: other native callbacks and Rust-side caches remain host resources. Only authored/trusted addons are qualified; this is not an adversarial-addon containment guarantee.

## First actual addon

`addons/AzerothBenchObserver` is authored code, not copied install content. Install into the client's own local-state AddOns root. Its actual TOC/Lua/XML must load via the ordinary loader. It exercises chunk arguments, ordered lifecycle events, XML widgets, OnUpdate, pointer click dispatch, player-state readers and ordinary SavedVariables persistence. It has no movement/combat/GM/evaluator capability.

Acceptance requires fixture tests followed by a bounded graphical dedicated-account run with a rendered status/button, pointer-originated sample, real observed player health/name/GUID/level, successful reload/persistence and normal movement/logout/reconnect. Scripts/errors/data manifests and frame capture are retained outside git. Existing ground authority/root order/reconnect fences are unchanged and requalified after integration.
